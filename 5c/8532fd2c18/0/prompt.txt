## Design constraints
- Replace the single slot with a small cache keyed by network audio URL: entry =
  `{blobUrl, nav: ChapterWindow|null, abort}`; walk forward from the loaded chapter
  via each entry's `nav.next` to fill up to N; revoke blobs when the loaded chapter
  moves past them or a manual jump makes them unreachable; abort in-flight fetches
  that become unreachable. Bound memory (chapters are ~15–20 MB WAV; 3 ahead ≈ 60 MB
  — acceptable, don't go higher). Prev-direction blobs are out of scope.
- Fill trigger: on mount and on every swap (immediately), plus retry on `online` /
  `visibility-visible` and on `timeupdate` (throttled) so a failed fetch retries.
- Follow the reconciliation memory: `swapToChapter` stays the ONLY `audio.src`
  writer; `navTarget` stays `CHAPTER_WINDOW`-only; on swap the window advances from
  the consumed entry's `nav` (or goes empty — never stale). No new writers, no
  per-edge patches.
- Keep every existing `prefetch-*` event semantics where they still apply; add
  e.g. `prefetch-cache-evict`, `prefetch-horizon` (depth reached) — and add
  `navigator.onLine` + `connection?.effectiveType` to `prefetch-fail`/`prefetch-nav-fail`
  detail (we couldn't tell blackout from Doze in the incident logs).
- Add a Prometheus-visible signal only if trivial; logs are the priority.
